# Verified research findings (2026-10-25)
Each finding was produced by a researcher and then checked by an adversarial verifier against primary sources. Verdicts: confirmed, corrected (use the correction), refuted, unverifiable.

## tab-capture

### [CONFIRMED] Only video.displaySurface is a spec'd constraint; selfBrowserSurface/surfaceSwitching/monitorTypeSurfaces/preferCurrentTab/systemAudio/controller/windowAudio are top-level hint members with the stated Chrome versions and defaults; Firefox/Safari support none; two combinations throw TypeError; min/exact throw TypeError.

Chromium user_media_request.cc throws TypeError 'Self-contradictory configuration (preferCurrentTab and selfBrowserSurface=exclude)' and '(displaySurface=monitor and monitorTypeSurfaces=exclude)'; media_devices.cc sets selfBrowserSurface=exclude when absent and preferCurrentTab is not true. ### [CONFIRMED] grabFrame() timing is undefined by spec and Chromium waits for the NEXT frame (issue #212, hangs reported); tab capture is damage-driven but adding a sink triggers RequestRefreshFrame(); so always time-box grabFrame; video+canvas cannot hang.

Spec source (w3c/mediacapture-image index.bs): grabFrame 'takes a snapshot of the live video being held in track', rejects InvalidStateError if readyState not live, UnknownError on failure (e.g. rapid repeated calls), says nothing about which frame or timing. Issue #212 'Clarify grabFrame timing' is still open; last comment 2020-04-22 reports promises that never return. Current Chromium main confirms the mechanism: ImageCaptureFrameGrabber::GrabFrame calls MediaStreamVideoSink::ConnectToTrack with a SingleShotFrameHandler that resolves on the next OnVideoFrame, and MediaStreamVideoTrack::AddSink contains '// Request source to deliver a frame because a new sink is added.' followed by RequestRefreshFrame(). The cited Chromium commits (262fe18, 92f344b) could not be opened (googlesource blocked) but the behavior they describe is visible in current source, so confidence can be raised from medium to high.

Source: https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/imagecapture/image_capture_frame_grabber.cc

### [CONFIRMED] Chrome keeps producing frames for a captured background tab because tab capture calls WebContents::IncrementCapturerCount(size, stay_hidden=false, stay_awake=true), forcing kHiddenButPainting; the captured tab need not be visible.

Current Chromium main content/browser/media/capture/web_contents_frame_tracker.cc: `contents_->IncrementCapturerCount(capture_size, /*stay_hidden=*/false, /*stay_awake=*/true, /*is_activity=*/true)` (signature gained an is_activity argument). web_contents_impl.cc: a stay_hidden=false capturer increments visible_capturer_count_, and the page visibility computation returns PageVisibilityState::kHiddenButPainting when the tab is not VISIBLE but visible_capturer_count_ > 0. Commit 3aec32d verified on GitHub: '[composebox] Fix CopyFromSurface for background tabs' – 'CopyFromSurface() can fail for background tabs because the renderer may be throttled... setting the PageVisibilityState to kHiddenButPainting during the capture... by calling content::WebContents::IncrementCapturerCount()'. The chromium.org Mac-occlusion design doc and commits dc3c38b/92f344b/262fe18 could not be fetched (blocked); their quotes remain unverified but are consistent with the code.

Source: https://raw.githubusercontent.com/chromium/chromium/main/content/browser/media/capture/web_contents_frame_tracker.cc

### [CORRECTED] Conditional Focus (Chrome 109+): call controller.setFocusBehavior('focus-capturing-application') immediately after the promise resolves (same microtask); later calls throw or are no-ops after ~1 s; throws for monitor; values are 'focus-captured-surface' | 'focus-capturing-application'.

**Correction:** The enum has three values, not two: CaptureStartFocusBehavior = 'focus-capturing-application' | 'focus-captured-surface' | 'no-focus-change' (spec and Chromium capture_controller.idl). Note the doc discrepancy: Chrome's article lists only the first two, MDN's setFocusBehavior page lists only 'focus-captured-surface' and 'no-focus-change'; Chromium accepts all three, so 'focus-capturing-application' is fine. Also, once the window closes Chromium throws InvalidStateError ('The window of opportunity for focus-decision is closed.') rather than silently no-op'ing; the 1-second no-op is the browser-side timer described in the article.

BCD CaptureController/setFocusBehavior chrome 109, firefox/safari false. Chromium media_devices.cc enqueues a microtask (CloseFocusWindowOfOpportunity → FinalizeFocusDecision) after resolving, with a comment that a browser-side timer also backs it; capture_controller.cc throws InvalidStateError if finalized, if the track is not live, or if the surface is not a tab or window ('The captured display surface must be either a tab or a window.'). Archived Chrome article confirms: available from Chrome 109; promise resolves on a microtask; calling after that microtask throws; calls more than one second after capture starts are no-ops; throws if the user shared a screen; last invocation wins. WICG/conditional-focus README: window closes at the earlier of 1 s or one task after resolution; setTimeout is too late. A CaptureController is single-use: reusing it throws InvalidStateError 'A CaptureController object may only be used with a single getDisplayMedia() invocation.'

Source: https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/mediastream/capture_controller.cc

### [CONFIRMED] Re-grabbing frames never re-prompts (permission cannot be persisted; transient activation required per call); stream ends on 'Stop sharing', captured-tab close, or capturing-document navigation/reload, firing `ended`; `ended` is not fired for your own track.stop(); capture survives navigations inside the captured tab.

Spec: 'granted permissions cannot be persisted'; InvalidStateError without transient activation. MDN ended_event source lists 'The user revoked the permissions needed for the data to be sent' and 'The only case where the track ends but the ended event is not fired is when calling MediaStreamTrack.stop'. Chromium tab_capture.idl: 'Capture is maintained across page navigations within the tab, and stops when the tab is closed, or the media stream is closed by the extension.' Capture Handle spec: capturehandlechange fires when 'The captured application's top-level browsing context is navigated cross-document'. The Mozilla standards-positions quote about navigating the capturing document could not be fetched (not verified, but consistent with the capture-session being owned by the capturing document). Note there is no standard event when the user uses 'Share this tab instead' (surfaceSwitching); re-read getSettings() per capture as the report says.

### Missed but important
- CaptureStartFocusBehavior has a third value, 'no-focus-change', in both the spec and Chromium's IDL; Chrome's article omits it and MDN's setFocusBehavior page omits 'focus-capturing-application'. Chromium accepts all three, so either 'focus-capturing-application' or 'no-focus-change' keeps the tutor in front.
- A CaptureController is single-use: passing the same controller to a second getDisplayMedia() rejects with InvalidStateError ('may only be used with a single getDisplayMedia() invocation'). Create a new controller on every Reconnect.
- Chromium's getDisplayMedia TypeError messages are literal: 'Self-contradictory configuration (preferCurrentTab and selfBrowserSurface=exclude).' and 'Self-contradictory configuration (displaySurface=monitor and monitorTypeSurfaces=exclude).' Useful for log-grepping during development.
- HiDPI tab capture is no longer behind a flag in Chromium: VideoCaptureParams.is_high_dpi_enabled defaults to true and the auto-scaler is created unless GPU compositing is disabled. Large ideal width/height constraints will usually be honored by upscaling the renderer, so measure getSettings() rather than assuming CSS-pixel frames.
- Firefox Nightly ships with media.getusermedia.browser.enabled = true (value is @IS_NIGHTLY_BUILD@), so a Nightly user may see a tab-sharing option; Release/Beta do not. Do not special-case it.
- iOS 27 Safari evidence: BCD merged safari_ios '27' on 2026-10-14 after a BrowserStack collector pass plus two independent real-device reports (system whole-screen picker, video-only MediaStream). Apple's Safari 27.0 release notes do not announce it. Whole-screen capture on a phone shows the tutor app itself, so the iOS fallback (upload) stays correct; feature-detect rather than UA-sniff.
- Chrome's tab pane shows favicon + title rows and a single preview of the selected tab (strings 'Select a tab to share', 'Preview of shared tab'); only Window/Entire Screen show live thumbnails. Write the student-facing copy around 'find the SAT Suite Question Bank tab by name and check the preview', not thumbnails. A 'This Tab' pane only appears with preferCurrentTab:true.
- windowAudio (Chrome 141) is partial: default 'system', only 'exclude'|'system' accepted ('window' unsupported); BCD records Edge defaulting to 'exclude' before Edge 142. Irrelevant with audio:false but worth knowing if audio is ever added. The spec also has `audioSelection` and a `restrictOwnAudio` constraint.
- Captured Surface Control details: forwardWheel() can only be successfully invoked from `click` or `input` events (MDN), the permission policy 'captured-surface-control' defaults to self (cross-origin iframes need allow=), a `zoomlevelchange` event exists and the zoom can change under you (user or surface switch), and Chrome's bar shows 'Shared tabs can be scrolled and zoomed' when granted. Call resetZoomLevel() on connect so a previously zoomed Question Bank tab does not confuse extraction.
- Chromium's ImageCapture.grabFrame() attaches a fresh sink per call, and MediaStreamVideoTrack::AddSink requests a refresh frame, so on current Chrome a static tab normally yields a frame; the spec still defines no timing and issue #212 is open, so keep the timeout race.
- Chrome's tab-sharing infobar now also offers 'View tab: <origin>' / 'Switch to captured tab' buttons; students may click these and land on the Question Bank tab, which does not end capture but changes focus; Conditional Focus only controls the initial focus.
- BCD's `MediaStreamTrack.getSettings` has no displaySurface sub-feature; Firefox's MediaTrackSettings WebIDL exposes Mozilla-specific `mediaSource` instead, so `getSettings().displaySurface` is undefined on Firefox (treat undefined as 'not a tab').
- Capture Handle's `handle` string is limited to 1024 UTF-16 chars (TypeError) and setCaptureHandleConfig is top-level-only; irrelevant for College Board's tab but relevant if the tutor ever captures its own second tab.
- Verification note: developer.chrome.com, MDN, caniuse, webkit.org, chromium.googlesource.com, Bugzilla and addpipe were all policy-blocked from this container as well; every claim above was checked against GitHub raw mirrors of the same primary sources (mdn/content, mdn/browser-compat-data v8.1.7, chromium/chromium 158.0.8124, mozilla-firefox/firefox, WebKit/WebKit, W3C/WICG/screen-share spec repos, the archived GoogleChrome/developer.chrome.com articles) and Apple's Safari release-notes data.

### Recommendations that survived verification
- Target Chrome/Edge desktop for the Capture button and feature-detect `!!navigator.mediaDevices?.getDisplayMedia && 'CaptureController' in window`; show PDF/paste/screenshot upload on Firefox, Safari and iOS (Safari/Firefox share only windows/screens; iOS 27 appears to support whole-screen capture only, which is useless for capturing another tab).
- Request the stream once per session with `video:{displaySurface:'browser', width:{ideal:3840}, height:{ideal:2160}, frameRate:{max:5}}, audio:false, controller:new CaptureController(), selfBrowserSurface:'exclude', surfaceSwitching:'include', monitorTypeSurfaces:'exclude'`; use only ideal/max (min/exact and `advanced` throw TypeError); never combine monitorTypeSurfaces:'exclude' with displaySurface:'monitor' or selfBrowserSurface:'exclude' with preferCurrentTab:true. Create a fresh CaptureController for every (re)connect because a controller is single-use.
- Immediately after the promise resolves (no intervening await) check `track.getSettings().displaySurface` and, if it is 'browser' or 'window', call `controller.setFocusBehavior('focus-capturing-application')` (or 'no-focus-change'; all three enum values are valid in Chromium). Wrap in try/catch: it throws InvalidStateError for monitors or if the microtask window has closed.
- Grab stills with a hidden, playing <video> + OffscreenCanvas.drawImage → convertToBlob('image/png'); wait for `await video.play()` and one requestVideoFrameCallback before the first capture. Treat ImageCapture.grabFrame() as an optional Chrome/Safari-26+ fast path raced against a ~1.5 s timeout (Chromium requests a refresh frame when grabFrame attaches its sink, so hangs are unlikely but the spec leaves timing undefined). Do not use MediaStreamTrackProcessor.
- Keep the MediaStream and hidden video in a module-level store or root-layout React context so Next.js client navigation keeps the capture alive; a hard reload ends it (the spec forbids persisting the permission), so expose a one-click Reconnect that re-opens the picker from a click handler.
- Listen for `track.addEventListener('ended', …)` and switch to Reconnect; before each capture check `track.readyState === 'live'` and re-read `getSettings().displaySurface` because 'Share this tab instead' retargets the same track with no dedicated event.
- Do the crop yourself: show a small live preview, let the student drag a rectangle once, persist it, and pass it to drawImage; CropTarget/RestrictionTarget are self-capture-only and cannot crop College Board's tab. Alternatively send the whole frame and tell the extraction model to ignore browser/site chrome.
- Behind `!!window.CaptureController?.prototype.forwardWheel` (Chrome 136+ desktop), call `controller.forwardWheel(previewEl)` and `increaseZoomLevel()` from click/input handlers only (first call prompts for 'captured-surface-control'), call `resetZoomLevel()` on connect, listen for `zoomlevelchange`, and catch NotSupportedError when the shared surface is not a tab.
- Measure the captured resolution on the real machine via `track.getSettings()` (width/height and screenPixelRatio on Chrome 136+). HiDPI tab capture is on by default in current Chromium (no flag), so large ideal constraints normally yield upscaled frames; use the zoom API if text is still too small.
- Never write the Blob to disk or a bucket; POST it in memory to the Next.js route handler that calls the model and drop it after the response. Keep PNG for text fidelity; WebP/JPEG at quality ≥0.9 is acceptable if payload size matters.
- For v2 prefer a Chrome extension built on chrome.sidePanel (Chrome 114+, MV3; sidePanel.open() 116+) + chrome.tabs.captureVisibleTab (host permission for satsuitequestionbank.collegeboard.org, max 2 calls/s, captures the active tab only) over chrome.tabCapture; it removes picker/reload friction and lets you read the question DOM via chrome.scripting.executeScript. Keep the web getDisplayMedia path as the no-install baseline.
- Write the picker copy to match Chrome's real UI: 'In the "Chrome Tab" list pick the tab named SAT Suite Question Bank, check the preview, then click Share. Your screen is not recorded; one picture is taken only when you press Capture.' Verify the DisplayMediaStreamOptions type in your TS lib.dom and add a `declare global` augmentation for any missing members (monitorTypeSurfaces, preferCurrentTab, controller, surfaceSwitching, selfBrowserSurface, systemAudio, windowAudio) and for the three-value CaptureStartFocusBehavior.

- Primary store: Supabase Free (one project) still stands. Provision via MCP as list_organizations → get_cost(type 'project') → confirm_cost → create_project(name, region nearest the student e.g. us-east-1, organization_id, confirm_cost_id) → poll get_project until ACTIVE_HEALTHY (watch for INIT_FAILED). Or use the Management API POST /v1/projects with {name, organization_slug, db_pass} and no desired_instance_size (defaults to Nano on Free), or `vercel install supabase` (Free plan is selectable; injects POSTGRES_URL / POSTGRES_URL_NON_POOLING / SUPABASE_SECRET_KEY / NEXT_PUBLIC_SUPABASE_*). Create the sb_secret_ key in the dashboard; reset the DB password only if you will use a Postgres driver (the MCP-generated one is not returned and the API cannot reveal it).
- Treat pausing as a product risk. Keep the once-daily Vercel Hobby cron ("0 9 * * *", ±59 min, production deployments only) hitting /api/cron/keepalive, authenticated with CRON_SECRET compared via crypto.timingSafeEqual on equal-length digests, performing 3–5 real queries through the same data path as the app and returning non-200 on failure. Keep the owner's email current so the ~1-week warning arrives. In the UI, detect a paused project and show a 'Resume in the Supabase dashboard' message; if you add an admin 'Restore' button, call POST /v1/projects/{ref}/restore with a scoped PAT holding project_admin_write and poll status for RESTORING → ACTIVE_HEALTHY / RESTORE_FAILED. The restore window is 1 year (verify in the dashboard banner at the time; Supabase's own search index still says 90 days). Keep the schema plain Postgres so moving to Neon Free (auto-resume in hundreds of ms, 100 projects, `vercel install neon`) is a connection-string change.
- Runtime data access for v1: @supabase/supabase-js with the server-only secret key (SUPABASE_URL / SUPABASE_SECRET_KEY, never NEXT_PUBLIC_). It is HTTPS to PostgREST with no sockets, IPv6, prepared-statement or pipelining concerns, and later swaps to a user-scoped @supabase/ssr client. Never hand-roll a request that puts sb_secret_ in an Authorization: Bearer header; it must go in the apikey header (supabase-js does this). If you prefer typed SQL now: Drizzle + postgres.js with `postgres(DATABASE_URL_6543, { max: 1, prepare: false, ssl: 'require' })` at module scope, drizzle-kit migrations over the 5432 session pooler or POSTGRES_URL_NON_POOLING, username postgres.<ref>, and beware Postgres.js pipelining. Generate types with MCP generate_typescript_types or `supabase gen types`.
- Passcode gate (Next.js 16): proxy.ts (Node runtime; edge not supported) with a negative matcher that excludes api/cron, _next/static, _next/image and static assets; verify a jose HS256 JWT from SESSION_SECRET (`openssl rand -base64 32`) and redirect to /unlock. /unlock Server Action verifies the passcode by comparing HMAC-SHA256(SESSION_SECRET, submitted) with HMAC-SHA256(SESSION_SECRET, PASSCODE) via crypto.timingSafeEqual (equal-length digests), or verifies a stored crypto.scrypt hash (use argon2 only if the Vercel project runs Node ≥ 24.7), then sets the cookie { httpOnly: true, secure: true, sameSite: 'lax', path: '/', expires: +30d } with payload { sub: OWNER_USER_ID, pv: PASSCODE_VERSION }. Call a DAL requireSession() at the top of EVERY Server Action and Route Handler (Next.js: Server Functions on excluded paths bypass Proxy; React cache() does not dedupe outside a render pass). Rate limit with one Hobby WAF rate-limit rule configured in the dashboard (1 rule, fixed window, IP/JA4, 10s–10min, per-region counters) plus a Postgres unlock_attempts table with lockout; the exact `vercel firewall rules add` rate-limit flags were not verifiable, so check `--help` before scripting them.
- Schema now for Supabase Auth + RLS later: every table gets id uuid default gen_random_uuid(), user_id uuid not null default '<OWNER_USER_ID>' (no FK to auth.users yet), created_at/updated_at timestamptz, and a btree index with user_id leading (e.g. (user_id, created_at desc)). Enable RLS on day one, `revoke all ... from anon, authenticated; grant select, insert, update, delete ... to authenticated;`, and write four per-operation policies `to authenticated using/with check ((select auth.uid()) = user_id)` (UPDATE needs a SELECT policy; views need `with (security_invoker = true)`). The secret-key client bypasses these in v1, so the cutover is: sign the student up, `update <table> set user_id = '<auth uid>' where user_id = '<OWNER_USER_ID>'`, add `references auth.users(id) on delete cascade`, drop the default, switch to @supabase/ssr (getClaims in proxy.ts, apply the Cache-Control/Expires/Pragma headers setAll hands you), remove the passcode path. Test with `supabase test db` (pgTAP).
- Reject Turso and Upstash as primary store (confirmed: Turso is SQLite, archives free DBs after 10 days and needs an explicit unarchive; Supabase acquired it on 2026-10-02 with 'nothing changes' for now; Upstash is Redis/Vector/QStash only with conflicting 30-day vs 1-week inactivity rules). Neon Free and Prisma Postgres Free remain the real Postgres fallbacks: Neon for never-archived, instant-resume compute; Prisma for per-operation billing with no inactivity rule but a hard 200k ops/month cap where SELECT 1 counts (and only 10 direct connections, 5 reserved) — so never point a keep-alive at Prisma, and if you use it, add DATABASE_URL_POOLED (pooled.db.prisma.io) alongside the integration's direct DATABASE_URL/POSTGRES_URL/PRISMA_DATABASE_URL.
- Secrets hygiene: store keys only as Vercel server env vars (no NEXT_PUBLIC_), prefer sb_secret_ over the legacy service_role JWT (legacy keys stop working at end of 2026 and secret keys refuse browser User-Agents), rotate if they ever appear in logs, set ssl:'require'/sslmode=require on any Postgres driver, and run migrations over the 5432 session pooler because Free-plan direct connections are IPv6-only. Take your own periodic pg_dump: Free has no downloadable automated backups.
